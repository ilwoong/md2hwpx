# Markdown → HWPX 변환

## 목적

Markdown 파일을 읽어 템플릿 HWPX 문서 뒤에 내용을 추가하고, 새 HWPX 파일로 저장한다.
글자·문단 모양은 템플릿에 정의된 스타일을 그대로 사용한다.

## 범위

- 포함: CommonMark 전체(헤딩, 문단, 강제 줄바꿈, 코드블록, 목록, 인용문, 수평선, 이미지, 링크, 강조, 이스케이프,
  참조식 링크, 임의 깊이의 블록 중첩)와 GFM 표·취소선, 각주, 그리고 이 프로젝트의 표기
  (표·그림 캡션, `[TOC]` 차례, `\newpage` 쪽 나누기).
- 제외: 원시 HTML (글자 그대로 들어간다).
- 다이어그램 코드블록은 변환 전에 [diagram-rendering.md](diagram-rendering.md) 의
  `render_diagrams` 로 이미지 링크로 바꿔 둔다. `convert` 는 다이어그램을 렌더링하지 않는다.

## 외부 의존성

[python-hwpx](https://github.com/airmang/python-hwpx) 를 사용한다.

- 템플릿 열기: `HwpxDocument.open`
- 저장: `HwpxDocument.save_to_path`

Markdown 파싱에는 [markdown-it-py](https://github.com/executablebooks/markdown-it-py) 와
[mdit-py-plugins](https://github.com/executablebooks/mdit-py-plugins) (각주) 를,
코드블록 구문 강조에는 [Pygments](https://pygments.org/) 를 사용한다.

## 템플릿 요구사항

템플릿에는 다음 이름의 문단 스타일이 있어야 한다. 스타일은 id 가 아니라 이름으로 찾는다.

| 스타일 | 용도 |
|--------|------|
| `개요 1` ~ `개요 6` | 헤딩 |
| `본문` | 헤딩을 제외한 본문 문단, 그림·표·코드블록을 담는 문단 |
| `표그림제목` | 표·그림·코드블록 캡션 |

템플릿의 기존 문단(첫 문단의 구역 설정 포함)은 그대로 두고, 그 뒤에 변환 결과를 추가한다.

## Front matter

- 파일 맨 앞(UTF-8 BOM 뒤 포함)의 YAML front matter 는 문서 내용이 아닌 메타데이터이므로 변환하지 않고 버린다.
- 형태: 첫 줄이 `---`, 그 뒤 처음 나오는 `---` 또는 `...` 줄까지 (각 줄 끝 공백 허용).
- 닫는 줄이 없거나 파일 맨 앞이 아닌 `---` 블록은 front matter 가 아니므로 본문으로 둔다.
- 파일을 읽을 때(`read_markdown`) 제거하므로, 폴더 입력은 파일마다 각자의 front matter 를 제거한다.
- TOML(`+++`) front matter 는 지원하지 않는다.

## 변환 규칙

Markdown 은 [markdown-it-py](https://github.com/executablebooks/markdown-it-py) 로 파싱한다.

- 프리셋: `commonmark` + GFM 표(`table`) + 취소선(`strikethrough`), 각주는 `mdit-py-plugins` 의 `footnote_plugin`.
- `html` 옵션은 끈다: 원시 HTML 은 글자 그대로 들어간다.
- 블록과 인라인의 문법 판단(헤딩, 목록 수준, 인용문, 코드블록 시작·끝, 강조 짝 맞추기, 이스케이프,
  참조식 링크 등)은 모두 CommonMark 규칙을 따른다. 아래는 파싱 결과(블록 트리)를 HWPX 로 옮기는 규칙이다.
- 블록은 어떤 깊이로든 중첩될 수 있다. 목록 항목과 인용문 안의 블록에는 아래 "배치" 규칙의 여백과 선이 더해진다.

### 배치 (목록·인용문 안의 블록)

- 인용문 깊이 q, 들어 있는 목록 항목의 수준 l(최대 3) 일 때 블록 문단의 왼쪽 여백:
  `본문` 왼쪽 여백 + q × 1000 + l × 1000 HWPUNIT.
- q > 0 이면 문단 테두리: 왼쪽에만 실선 0.7mm `#A6A6A6`, 글과의 간격 850 HWPUNIT,
  "문단 테두리 연결" 을 켜서 이어지는 인용 문단의 선이 하나로 이어지게 한다 (수평선 문단은 선을 그리지 않는다).
- 표·코드블록·그림은 그것을 담는 문단에 이 여백과 선을 적용한다.
- 헤딩에는 적용하지 않는다 (`개요` 스타일 그대로).

### 헤딩

- ATX(`#` 1~6개)와 Setext(`===` 는 1, `---` 는 2) 헤딩.
- `add_heading(level=N)` 으로 추가하며 `개요 N` 스타일이 적용된다.
- 문단 바로 다음 줄의 `---` 는 Setext 헤딩 2 가 된다. 수평선은 앞에 빈 줄을 둔다.

### 문단

- 문단 하나를 `본문` 문단 하나로 만든다. 줄바꿈(soft break)은 공백 하나로,
  강제 줄바꿈(줄 끝 공백 2칸 이상 또는 `\`)은 한/글 줄바꿈(`lineBreak`)으로 넣는다.
- 문단 안의 줄 가운데 다음 줄은 문단을 나눈다:
  - `[TOC]`(대소문자 무시), `\newpage`, `\pagebreak` 만 있는 줄 → 아래 "차례", "쪽 나누기".
  - 이미지 → 아래 "이미지". 이미지 앞뒤의 글은 따로 문단이 된다.
- 앞뒤 공백만 남는 조각은 버린다.

### 코드블록

- 펜스 코드블록과 들여쓴(4칸) 코드블록. 닫는 펜스가 없으면 문서 끝까지 코드다 (CommonMark).
- 1×1 표 하나로 만든다. 코드 한 줄이 셀 안의 문단 하나가 되며, 줄 앞 공백을 유지한다.
  표처럼 쪽을 넘으면 다음 쪽으로 이어진다 (아래 "표" 참고).
- 셀 문단 서식: 글꼴 `D2Coding`, 크기 9pt, 줄간격 140%.
- 구문 강조:
  - info string 의 첫 단어를 Pygments 렉서 이름으로 사용한다 (`python`, `js`, `sh` 등 별칭 포함).
  - 언어가 없거나(들여쓴 코드블록 포함) Pygments 가 모르는 이름이면 강조하지 않는다 (모두 기본 글자색).
  - 토큰마다 글자 조각(run)을 나누고, Pygments `default` 스타일의 글자색·굵게·기울임을 적용한다.
    배경색·밑줄은 적용하지 않는다.
  - 여러 줄에 걸친 토큰(예: 여러 줄 문자열)은 줄마다 같은 서식으로 나눈다.

### 표 (GFM)

- 셀 수는 파서가 머리 행에 맞춘다 (모자란 칸은 빈 셀, 넘치는 칸은 버림). `\|` 는 `|` 문자다.
- 머리 행: 굵게, 셀 배경 `#D9D9D9`(회색).
- 열 정렬: 구분 행 기준으로 머리 행을 포함한 해당 열 전체에 적용한다.

| 구분 행 | 정렬 |
|---------|------|
| `:--` | 왼쪽 |
| `:-:` | 가운데 |
| `--:` | 오른쪽 |
| `---` | 지정하지 않음 (템플릿 기본값) |

- 셀 안의 인라인 서식·링크·각주를 적용한다. 셀 안의 이미지는 대체 텍스트로 넣는다.
- 표 폭은 python-hwpx 기본값(본문 폭)을 따른다.
- 표와 코드블록은 글자처럼 취급하지 않는다(`treatAsChar="0"`). 한/글은 글자처럼 취급한 표(python-hwpx
  `add_table` 의 기본)를 쪽에서 나누지 않아 쪽을 넘는 행이 잘리므로, 흐르는 표로 만들어 다음 쪽으로 이어지게 한다.
  - 쪽 경계에서는 python-hwpx 기본값(`pageBreak="CELL"`, 셀 단위로 나눔)으로 나눈다.
  - 가로 위치는 문단 기준(`horzRelTo="PARA"`)이다. 목록·인용문 안의 표도 문단 여백만큼 들여 놓인다.
- 열 너비는 내용 길이에 비례해 나눈다.
  - 열의 가중치 = 그 열(머리 행 포함)에서 가장 긴 셀의 표시 폭. 최소 4.
  - 표시 폭은 전각 문자(한글 등, East Asian Width `W`/`F`)를 2, 나머지를 1로 센다.
    인라인 서식 기호(백틱, `**` 등)는 세지 않는다.
  - 표 폭을 가중치 비율로 나눠 `set_column_widths` 로 적용한다.

### 이미지

- 문단 안의 이미지(인라인, 참조식 `![글][id]` 모두)는 그 자리에서 문단을 나눠 그림 문단 하나가 된다.
  헤딩과 표 셀 안의 이미지는 대체 텍스트로 넣는다.
- 경로는 Markdown 파일이 있는 폴더 기준이며, 퍼센트 인코딩(`%20` 등)은 풀어서 찾는다.
  확장자를 이미지 형식으로 사용한다.
- 크기는 항상 원본 비율을 유지한다.
  - 다이어그램 이미지(`render_diagrams` 가 만든 `mermaid-<해시 12자리>.png`, `plantuml-<해시 12자리>.png`)는
    폭을 본문 폭에 맞춘다.
  - 그 밖의 이미지는 96 DPI 기준 원래 크기로 넣는다 (1픽셀 = 75 HWPUNIT).
  - 어느 쪽이든 본문 폭이나 본문 높이를 넘으면 넘지 않도록 줄인다. 작은 이미지를 키우지는 않는다.
    - 본문 폭: 쪽 폭 − 쪽 좌우 여백 − 제본 여백 − `본문` 스타일의 문단 좌우 여백.
    - 본문 높이: 쪽 높이 − 위쪽·아래쪽 여백 − 머리말·꼬리말 여백.
      캡션이 있으면 캡션 자리로 2500 HWPUNIT(간격 850 + 10pt 한 줄)을 뺀다.
- 픽셀 크기는 PNG, GIF, JPEG 헤더에서 읽는다.
  읽지 못하는 형식이면 python-hwpx 기본값(폭 14400 HWPUNIT, 약 51mm)을 따른다.

### 캡션

- `[표] 제목` 으로 시작하는 문단 조각 다음에 표 또는 코드블록이 오면 그 개체의 캡션이 된다.
- `[그림] 제목` 으로 시작하는 문단 조각 다음에 이미지가 오면 그 이미지의 캡션이 된다.
  같은 문단의 다음 줄에 이미지가 있어도 되고, 다음 블록이 이미지로 시작하는 문단이어도 된다.
- 캡션 줄과 개체 사이의 빈 줄은 허용한다 (표는 빈 줄 없이 바로 이어 써도 된다).
- 뒤에 해당 개체가 오지 않는 `[표]` / `[그림]` 조각은 일반 문단으로 처리한다.
- 캡션 문구: `[표 N] 제목`, `[그림 N] 제목`. 제목의 인라인 서식은 적용하고 각주 참조는 버린다.
  `N` 은 문서 순서대로 1부터 매기며, 표(코드블록 포함)와 그림의 번호를 따로 센다.
  캡션이 없는 개체는 번호를 세지 않는다.
  번호는 고정 글자이며 한/글 자동 번호가 아니다.
- 위치: 표·코드블록은 위(`TOP`), 그림은 아래(`BOTTOM`).
- 캡션 문단에는 `표그림제목` 스타일의 스타일·문단 모양·글자 모양을 적용한다.

### 목록

- 항목의 첫 문단의 첫 글 조각이 글머리표·번호 문단이 된다 (첫 문단이 그림으로 시작하면 빈 번호 문단).
  그 문단의 나머지 조각(그림, 이어지는 글 등)은 아래 "나머지 블록" 처럼 들여 놓는다. 글머리표·번호 문단은 `본문` 스타일이며,
  python-hwpx `styles.apply_list_format` 으로 글머리표·번호 서식과 수준을 적용한다.
  - 모양은 python-hwpx 기본값이다: 글머리표 `-` / `○` / `□`, 번호 `1.` / `1.1.` / `1.1.1.`.
  - 수준은 최대 3이며, 더 깊은 항목은 3수준으로 둔다.
  - 왼쪽 여백: 배치 여백 + (수준 − 1) × 1000 HWPUNIT (템플릿 `개요` 스타일의 수준 간격).
- 항목의 나머지 블록(문단, 코드블록, 표, 인용문 등)은 번호 없이 한 수준 더 들여 놓는다. 하위 목록은 다음 수준이다.
- 번호 매기기:
  - 번호 목록의 첫 항목은 새 번호로 시작하며, 시작 숫자가 1이 아니면 그 숫자부터 매긴다.
  - 같은 목록의 다음 항목은 그 목록의 번호 정의에 이어 매긴다. 사이에 다른 목록이 중첩돼 있어도 그렇다.
  - 번호 항목 안에 든 번호 목록은 바깥 항목과 같은 번호 정의를 쓴다 (한/글이 하위 수준 번호를 매김).
- 문단 중간에서 목록이 시작되는지는 CommonMark 규칙을 따른다 (번호 목록은 1 로 시작할 때만).

### 수평선

- `---`, `***`, `___` (사이 공백 허용). 빈 `본문` 문단에 아래쪽 테두리(실선 0.12mm, `#808080`)를 그려 나타낸다.

### 인용문

- 인용문 안의 블록은 깊이가 하나 늘어난 배치로 쓴다 (위 "배치"). 인용문 안에는 어떤 블록이든 올 수 있다.
- 인용문 안의 문단은 `본문` 스타일이며 인라인 서식을 적용한다.

### 각주

- `[^id]: 내용` 정의(들여쓴 이어지는 줄, 여러 문단 포함)와 `[^id]` 참조. 문법은 `footnote_plugin` 을 따른다.
- 참조 자리에 한/글 각주(python-hwpx `notes.add_footnote`)를 단다: 헤딩, 문단, 목록 항목, 인용문, 표 셀.
  번호와 모양은 템플릿의 각주 설정을 따르며 한/글이 매긴다 (id 는 번호에 쓰이지 않는다).
- 각주 본문 문단에 인라인 서식과 링크를 적용한다. 정의의 문단들은 줄바꿈으로 이어 한 문단에 넣는다.
  정의 안의 문단이 아닌 블록(목록, 코드블록 등)과 각주 안의 각주 참조는 넣지 않는다.
- 정의가 없는 `[^id]` 는 글자 그대로 둔다.
- 같은 id 를 여러 곳에서 참조하면 참조마다 같은 내용의 각주가 따로 생긴다.

### 차례

- `[TOC]` 줄(대소문자 무시)을 차례 자리로 쓴다. 첫 번째 표지만 쓰고 나머지는 무시한다.
- 변환이 끝난 뒤 그 자리에 한/글 차례 필드(python-hwpx `add_native_toc`)를 넣는다.
  제목은 `차례`, 헤딩 3수준(`개요 1`~`개요 3`)까지 넣는다 (처음 저장하는 항목도 3수준까지).
- 항목의 쪽 번호는 추정값이다. 필드를 "dirty" 로 표시하므로 한/글이 처음 열 때 차례를 다시 만들어
  올바른 항목과 쪽 번호로 바꾼다.
- 한/글은 차례를 다시 만들 때 바탕글 문단도 모으므로, 차례를 넣기 전에 바탕글 문단(표·코드블록 셀 등)의
  스타일을 `본문` 으로 바꾼다 (문단 모양은 그대로).
- 헤딩이 하나도 없으면 차례를 넣지 않는다.

### 쪽 나누기

- `\newpage` 또는 `\pagebreak` 줄 (pandoc 관례). Markdown 표준 문법은 없다.
- 그 뒤에 오는 첫 문단(헤딩, 문단, 표·그림을 담는 문단, 목록 항목 등)에 "쪽 나눔"(`pageBreak="1"`)을 켠다.
- 바로 뒤가 `[TOC]` 이면 차례 제목 문단에서 쪽을 나눈다.
- 뒤에 아무 문단도 없으면 무시한다.

### 인라인 서식

- 헤딩, 문단, 목록 항목, 인용문, 표 셀, 캡션, 각주 본문에 적용한다.
- 기호는 지우고, 서식이 바뀌는 곳마다 글자 조각(run)을 나눈다.
  지정하지 않은 글자 모양(크기, 머리 행 굵게, 캡션 스타일 등)은 감싼 문단의 것을 따른다.
  서식이 같은 이웃 조각은 하나로 합친다.

| 파서 결과 | HWPX |
|-----------|------|
| 코드 (`` `코드` ``) | 글꼴 `D2Coding` |
| 강조 (`*`, `_`) | 기울임 |
| 강한 강조 (`**`, `__`) | 굵게 |
| 취소선 (`~~`) | 취소선 |
| 링크 (`[글](URL)`, `[글][id]`, `<URL>`) | 한/글 하이퍼링크 필드 (python-hwpx `add_hyperlink`), 파란 글자·밑줄 |

- 서식은 겹칠 수 있다 (`***a** b*` → `a` 는 굵게 + 기울임, ` b` 는 기울임).
- 링크 텍스트 안의 서식도 적용하며, 서식이 다른 조각마다 같은 URL 의 하이퍼링크 필드를 만든다.

### 스타일 적용

- 헤딩을 제외한 본문 쪽 문단(일반 문단, 이미지·표·코드블록을 담는 문단)에는
  `본문` 스타일과 그 스타일의 문단 모양을 적용한다.
  이전 문단(예: 헤딩)의 문단 모양을 물려받지 않는다.
- 표·코드블록 셀 안의 문단은 `본문` 스타일을 적용하지 않는다(셀 기본 문단 모양 유지).

## 성능

100쪽이 넘는 문서를 다루므로, python-hwpx 의 비용이 문서 크기에 비례하는 호출을 반복하지 않는다.

- 스타일(`본문`, `표그림제목`, `개요 N`)은 변환을 시작할 때 이름으로 한 번만 찾고, 이후에는 `Style` 객체를 넘긴다.
  python-hwpx 는 이름으로 찾을 때마다 header.xml 전체를 훑는데, header.xml 은 변환 중 글자·문단 모양이 늘며 커진다.
- 본문 폭·높이·왼쪽 여백은 한 번만 계산한다.
- 문단 모양·글자 모양·테두리(`ensure_paragraph_format`, `ensure_run`, `ensure_border_fill`)는 같은 요청의 결과를 기억한다.
  python-hwpx 는 요청마다 문서의 모든 모양과 구조를 비교한다.
- 문단 수는 `doc.paragraphs`(모든 문단의 래퍼를 만듦) 대신 구역 XML 의 `hp:p` 자식 수로 센다.
- 목록 서식(`apply_list_format`, 호출마다 모든 문단을 나열)은 새 번호 목록과, 처음 쓰는 글머리표 수준·번호 정의의 수준에만 부르고,
  나머지 항목은 처음 얻은 `hh:heading` 을 그대로 적용한다.

측정 (문단 약 2,000개·표 240개, 100쪽 이상): 29.6초 → 15.4초. 약 300쪽(문단 3,900개): 112.5초 → 57.1초.
두 경우 모두 변환 결과(문단별 글자·스타일·문단 모양·글자 모양, 표 너비, 그림 크기)는 최적화 전과 같다.

남은 시간의 대부분은 python-hwpx 내부이며, 문서 크기에 대해 제곱으로 늘어나는 것도 있다
(차례의 헤딩 앵커 확인, 각주 번호 계산, `apply_list_format` 의 문단 나열, 저장·검증 직렬화).
비공개 함수를 바꾸지 않고는 피할 수 없어 그대로 둔다.

## 공개 API (`md2hwpx.convert`)

```python
def read_markdown(md_path: Path) -> str
def convert(md_path: Path, template_path: Path, out_path: Path) -> None
def convert_markdown(markdown: str, base_dir: Path, template_path: Path, out_path: Path) -> None
```

- `template_path` 를 `HwpxDocument.open` 으로 열고, Markdown 을 변환해 추가한 뒤
  `save_to_path(out_path)` 로 저장한다. 템플릿 파일은 바뀌지 않는다.
- `convert_markdown` 은 Markdown 문자열을 받고, 이미지 경로를 `base_dir` 기준으로 찾는다.
  `convert` 는 `read_markdown` 으로 `md_path` 를 읽어 `md_path` 의 폴더를 기준으로 `convert_markdown` 을 부른다.
- `read_markdown` 은 파일을 UTF-8 로 읽고 front matter 를 제거한다.
  `convert_markdown` 은 front matter 를 제거하지 않으므로, 파일 내용을 넘길 때는 `read_markdown` 으로 읽은 문자열을 넘긴다.
- 저장하기 전에 python-hwpx `doc.validate()` (header·section XML 스키마 검증)를 실행한다.
  오류(error)가 있으면 저장하지 않고 `ConversionError` 를 발생시키며, 메시지에 `파트:줄: 내용` 목록을 담는다.
  경고(warning)는 저장을 막지 않는다.
- 템플릿에 필요한 스타일이 없으면 python-hwpx 의 `HwpxLookupError` 가 발생한다.
- 이미지 파일이 없으면 `FileNotFoundError` 가 발생한다.

```python
def missing_images(markdown: str, base_dir: Path) -> list[tuple[int, Path]]
```

- 코드블록 밖의 이미지(인라인·참조식 포함) 중 파일이 없는 것의 (1부터 센 줄 번호, 경로) 목록을 돌려준다.
  줄 번호는 이미지 경로가 적힌 문단 안의 줄이며, 참조식이라 경로가 문단에 없으면 문단 첫 줄이다.
  front matter 가 있어도 원본 줄 번호로 센다.

## 명령줄 (`md2hwpx.cli`)

```
md2hwpx INPUT [-o OUTPUT] [-t TEMPLATE.hwpx]
python -m md2hwpx INPUT [-o OUTPUT] [-t TEMPLATE.hwpx]
```

- `md2hwpx` 명령은 `pyproject.toml` 의 `[project.scripts]` 로 설치된다.
  Docker 이미지는 프로젝트를 설치하지 않으므로 `python -m md2hwpx` 를 쓴다.
- 인자 없이 실행하면 도움말을 stdout 에 쓰고 종료 코드 0 을 돌려준다.
- 입력(`INPUT`):
  - Markdown 파일이면 그 파일을 변환한다. 이미지 경로의 기준은 파일이 있는 폴더다.
  - 폴더면 그 폴더 바로 안의 `.md` 파일(하위 폴더 제외)을 이름 순으로 읽어, 빈 줄 하나를 사이에 두고 이어 붙인
    Markdown 하나로 변환한다. 이미지 경로의 기준은 그 폴더다. 캡션 번호는 파일을 넘어 이어진다.
  - 이름 순은 대소문자를 구분하지 않고, 숫자 부분은 크기로 비교한다 (`2.md` → `10.md`).
  - `.md` 파일이 없는 폴더는 오류다.
- 출력 경로:
  - 입력 이름: 파일이면 확장자를 뺀 이름, 폴더면 폴더 이름(`.` 도 실제 폴더 이름).
  - `-o`, `--output` 생략 시 현재 작업 폴더의 `입력 이름.hwpx`.
  - `-o` 가 이미 있는 폴더면 그 폴더의 `입력 이름.hwpx`, 아니면 `-o` 경로 그대로.
  - 그 경로에 파일이 있으면 덮어쓰지 않고, 확장자 앞에 `-1`, `-2` ... 를 붙여 처음으로 비어 있는 경로에 저장한다.
- `-t`, `--template` 생략 시 현재 폴더의 `template.hwpx` 를 쓴다.
- 처리 순서: 입력 읽기 → `render_diagrams` 로 다이어그램을 임시 폴더에 렌더링 → `convert_markdown`.
  다이어그램 PNG 는 HWPX 에 들어가므로 저장 후 임시 폴더와 함께 지운다.
- 성공하면 출력 파일 경로를 stdout 에 쓰고 종료 코드 0 을 돌려준다.
- 변환 전에 입력 파일마다 `missing_images` 로 이미지 파일을 확인한다. 없는 이미지가 있으면 모두
  `md2hwpx: <입력 파일>:<줄>: 이미지 파일이 없습니다: <경로>` 로 stderr 에 쓰고 종료 코드 1 을 돌려준다.
  줄 번호는 front matter 를 포함한 원본 파일 기준이다.
- 파일 입출력 오류(`OSError`), `DiagramError`, python-hwpx 오류(`HwpxError`), `ConversionError` 는
  `md2hwpx: <메시지>` 를 stderr 에 쓰고 종료 코드 1 을 돌려준다. 이때 출력 파일은 만들지 않는다.

| 강제 줄바꿈 | 공백 두 칸·`\`, 서식이 줄바꿈을 넘는 경우, 목록 항목·인용문 안 |
| 각주 | 참조 위치, 들여쓴 이어지는 줄, 각주 본문의 굵게·링크·여러 문단, 정의 없는 참조는 글자 유지, 표 셀, 코드블록 안 정의 유지 |
